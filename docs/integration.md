# Подключение Credit Risk Desk

Два проекта независимы. Copilot не импортирует Python-пакеты первого проекта и не требует его API для SQL-запросов. Интеграция проходит через пять представлений в существующей PostgreSQL-базе.

## 1. Подготовьте первый проект

Credit Risk Desk должен быть инициализирован с demo или Berka. В его базе должны существовать `raw.dataset`, `clean.accounts`, `clean.loans`, `clean.applications`. Чтобы вопросы о заявках были содержательными, сохраните несколько проверок через его интерфейс. Пустой журнал заявок — корректный пустой результат, а не повод выдумывать данные.

## 2. Один раз создайте представления

Из корня Copilot, используя административное подключение к базе первого проекта:

```powershell
$env:COPILOT_ADMIN_URL = 'postgresql://<admin>:<password>@<host>:<port>/<risk_desk_database>'
$env:COPILOT_READER_PASSWORD = '<отдельный пароль reader-роли>'
credit-copilot connect-risk-desk
Remove-Item Env:COPILOT_ADMIN_URL
Remove-Item Env:COPILOT_READER_PASSWORD
```

Команда выполняет `sql/risk_desk_views.sql`, выдаёт reader-роли USAGE/SELECT и включает read-only по умолчанию. Изменяются только новая схема `copilot_data` и права новой/предусмотренной reader-роли. Таблицы `clean` и `raw` не меняются.

Роли PostgreSQL общие для всего кластера. Если `credit_copilot_reader` уже существует, команда не меняет её пароль или административные флаги. Используйте текущий пароль; при неподходящих правах API откажется выполнять SQL. Существующую схему с другим источником команда не заменяет.

## 3. Переключите подключение Copilot

В `.env` второго проекта:

```dotenv
COPILOT_DATABASE_URL=postgresql://credit_copilot_reader:<password>@<host>:<port>/<risk_desk_database>
```

Перезапустите API. Провайдер может оставаться demo: известные SQL-планы будут выполняться на данных первого проекта. Для свободных вопросов независимо включается live.

Для API-контейнера localhost означает сам контейнер. На Docker Desktop добавьте в `.env` отдельную Compose-настройку `COPILOT_TARGET_DATABASE_URL=postgresql://credit_copilot_reader:<password>@host.docker.internal:<порт>/<risk_desk_database>` и выполните `docker compose up -d --force-recreate api`. Либо настройте общую Docker-сеть и имя сервиса. `COPILOT_DATABASE_URL` используется локальным Python-процессом; `COPILOT_TARGET_DATABASE_URL` — переопределение подключения внутри контейнера. Не передавайте API-контейнеру пароль администратора.

## Особенности отображения

- `loans.amount` переименован в `original_amount`, чтобы не путать выдачу с остатком.
- Заявки и причины проверок извлекаются из сохранённых JSON первого проекта.
- Время `created_at` приведено к UTC; `as_of` — отдельная дата расчётных данных.
- Score отсутствует, если модель в первом проекте была отключена. NULL сохраняется.
- Повторные проверки одного счёта остаются отдельными заявками; это не независимые исторические кредиты.
- Истории ежедневных снимков риска не появляется от подключения: соответствующие вопросы всё равно требуют уточнения.

Фактически проверенный результат на Berka — 682 кредита и сумма при выдаче 103 261 740 CZK. Это подтверждает работу адаптера, а не качество генерации SQL языковой моделью.
