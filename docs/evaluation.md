# Оценка качества

Нужно разделять работоспособность сервиса, устойчивость ограничений и смысловую правильность ответов LLM.

## Автоматические тесты

Проверяются запрещённые SQL-конструкции, обходы схемы через CTE/UNION, вызовы функций, роль PostgreSQL, лимиты, реальные ошибки группировки и их исправление, остановка после трёх попыток, API, экспорт, контекст диалога и экраны. LLM-адаптеры тестируются через httpx.MockTransport: это проверяет формат запроса и обработку ответа, но не доступность реального провайдера.

## Набор вопросов

`evals/cases.json` содержит 20 случаев: агрегаты портфеля, статусы, выдачи по месяцам, нагрузка, неизвестные значения, причины нарушений, уточнения и отказы. Для успешных ответов записан независимый эталонный SQL. Он выполняется через ту же read-only политику на выбранном источнике.

Сравнение использует мультимножество строк: сохраняется число повторов, игнорируются порядок строк, имена и порядок столбцов, числа округляются до шести знаков. Значения должны совпадать. Усечённый результат не засчитывается. Такое сравнение не проверяет формулировку объяснения, смысл названий столбцов, порядок ранжирования и качество графика; совпадение значений само по себе не является полной семантической проверкой.

В `demo` выбираются 12 поддерживаемых фиксированных сценариев. Они прошли 12/12. Это проверка схемы, SQL и маршрутов, **не accuracy языковой модели**; `llm_quality_measured=false`, `live_case_pass_rate=null`. Остальные восемь случаев пропущены явно.

В `live` выполняются все 20. Отчёт включает модель, режим данных, долю прошедших сценариев, медианную/максимальную задержку, число исправлений, SQL и результат каждого случая. Один вопрос запускается один раз, без подбора лучшего результата из повторов. Успешная генерация ещё не означает совпадение с эталоном.

```powershell
credit-copilot evaluate --output reports/evaluation-live.json
```

Команда в live использует настроенный внешний API и его оплачиваемые вызовы. В текущей реализации этот прогон не проводился из-за отсутствия ключа; результатов качества живой LLM нет.

## Как расширять

Добавляйте переформулировки, сложные соединения, неоднозначные даты, NULL и пустые выборки, сравнение версий моделей, конфликтующие указания пользователя. Отделяйте вопросы для настройки промпта от отложенной проверки. Для отчёта по модели фиксируйте её ID, версию промпта, зависимостей и снимок данных. Проверяйте не только SQL-исполнение, но и соответствие бизнес-смыслу, полноту отказа и понятность уточнения.

Системный промпт и каталог находятся в Git. Набор мал и открыт, поэтому доля прошедших сценариев не является универсальной оценкой способности модели анализировать кредитные данные.
