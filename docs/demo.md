# Демонстрация за пять минут

**0:00–1:00.** Откройте интерфейс и назовите два режима отдельно: provider=demo, data=synthetic. Объясните, что демопланы фиксированы, а PostgreSQL, проверки и граф исполнения настоящие. Для живой генерации нужен API модели.

Выберите «Покажи распределение кредитов по статусам». Покажите таблицу и график, раскройте SQL. Значения берутся из запроса, а не придумываются при пересказе.

**1:00–2:00.** Спросите «Какие заявки не прошли проверку и по каким причинам?». Покажите JOIN заявок и правил. Затем — заявки с нагрузкой выше 45% и заявки без данных о нагрузке. NULL не означает ноль.

**2:00–3:00.** Выберите «Покажи демонстрацию исправления SQL». Это явно подготовленный сценарий ошибки без LLM. В журнале видны попытка обратиться к неизвестному столбцу, отказ проверки, исправленный SQL и одно успешное выполнение. Ошибочный запрос до БД не дошёл.

**3:00–4:00.** На экране «Данные и SQL-проверка» введите `DELETE FROM copilot_data.loans`. Проверка остановит запрос, не выполняя его. Объясните вторую независимую границу — reader-роль PostgreSQL, и покажите тест, в котором DELETE запрещён даже после переключения транзакции в read-write.

**4:00–5:00.** Спросите «Как изменился риск портфеля?». Помощник уточнит постановку, поскольку снимков риска нет. Ответьте «По месяцам»: будет показана динамика выдач. Это другой, явно согласованный показатель. Скачайте JSON/CSV, откройте журнал.

Завершите демонстрацию разбором ограничений: 12/12 демосценариев не оценивают LLM. Для настоящего качества подключите модель и выполните 20 вопросов из eval-набора. Отдельно можно показать сохранённый результат интеграции с 682 кредитами первого проекта.
